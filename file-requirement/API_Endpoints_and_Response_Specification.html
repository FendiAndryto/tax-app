API Endpoints & Standard Response Specification

Target Stack: Laravel 11 Backend API ↔ React Native (Expo) Mobile App

Standard Response Envelope Rule:
All API endpoints must return a unified JSON envelope with success, data, and meta (or error on failure). This ensures consistent TypeScript typing (ApiResponse<T>) and centralized error handling across the mobile app.

1. Global Response Envelopes

Success Response Envelope (200 OK / 201 Created)

{
  "success": true,
  "data": { ... },
  "meta": {
    "timestamp": "2026-11-05T17:30:00+09:00",
    "request_id": "req_88f92a10",
    "tax_year": 2026
  }
}

Error Response Envelope (400 / 401 / 422 / 500)

{
  "success": false,
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "The given data was invalid.",
    "details": {
      "withholding_tax": ["Calculated withholding tax mismatch."],
      "invoice_number": ["Invoice number must start with 'T' followed by 13 digits."]
    }
  },
  "meta": {
    "timestamp": "2026-11-05T17:30:00+09:00",
    "request_id": "req_88f92a11"
  }
}

1. POS Payout & Tax Synchronization (Article 204 Compliance)

POST /api/v1/integrations/pos/sync

Verified Calculation Rule (Japanese Income Tax Act Article 204):
• Statutory Daily Allowance: 5,000 JPY × 20 attendance days = 100,000 JPY
• Taxable Base: 650,000 JPY - 100,000 JPY = 550,000 JPY
• Withholding Tax (10.21%): 550,000 JPY × 10.21% = 56,155 JPY
• Net Payout: 650,000 JPY - (56,155 JPY + 50,000 JPY Deductions) = 543,845 JPY
